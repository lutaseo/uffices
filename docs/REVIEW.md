## 2. 권한 구조 (신규 구축)

```
운영자 SUPER (우리)
 └─ 업체 등록 + 이용기간 설정 + 업체 관리자 계정 발급 / 정지 / 연장
     └─ 관리자 ADMIN (예: 더좋은집 대표)
         └─ 업체 모든 기능 + 실장 계정 발급, 메뉴별 권한 체크로 위임
             └─ 실장 MANAGER
                 └─ 관리자가 준 권한만 사용, 데이터 범위: 업체 전체 / 본인 작성 건만
```

- **업체(테넌트) 분리**: 모든 데이터에 `companyId`. 다른 업체 데이터는 조회 불가.
- **이용기간/정지**: 기간 밖이거나 정지된 업체는 로그인 차단 (로그인 중이어도 다음 요청에서 차단). 만료 14일 전부터 상단에 경고 표시.
- **권한 키** (`src/auth/permissions.js`): 계약 조회/등록/수정/삭제, 금액·입금 정보 보기, 전자계약 서명요청, 계약자 조회/편집, 일정 조회/수정, 알림톡, 엑셀, 통계.
  - 새 기능을 만들 때 키 하나만 추가하면 권한설정 화면·메뉴 노출·서버 검사에 모두 반영됩니다.
- **위임 제한**: 관리자는 자신이 가진 권한 이상을 실장에게 줄 수 없음 (서버 측에서 걸러냄).
- **금액 숨김**: `금액·입금 정보 보기` 권한이 없으면 서버가 금액 필드를 아예 내려주지 않음.

테스트 계정 (개발 모드 로그인 화면에도 표시):

| 역할 | 아이디 | 비밀번호 |
|------|--------|----------|
| 운영자 | super | super1234 |
| 관리자(더좋은집) | admin | admin1234 |
| 실장(본인 건만, 금액 숨김) | manager | manager1234 |

## 3. 이번에 구현한 기능

- **로그인 / 로그아웃 / 비밀번호 변경**, 역할별 메뉴 노출
- **계약관리**
  - 날짜 기간검색: 계약일 · 시공예정일(1~3차 중 하나라도) · 시공완료일 · 취소일 · 등록일 + [오늘/이번주/이번달/지난달/3개월]
  - 아파트명/동/호/계약자명/전화번호(하이픈 무관) 검색, 브랜드/구분/접수형태/시공상태/전자계약상태/작성자/기사 필터, 정렬
  - 합계: 총건수(완료/취소), 실계약금(할인·상품권), 입금(카드/현금/계좌이체별), 남은금액, 취소금액 — 취소 건은 합계에서 제외
  - 등록/수정: 시공일정 최대 3회차 + 회차별 기사 배정, 시공총액/할인/상품권/입금내역 → 실계약금·잔액 자동계산
  - 상태를 시공완료/취소로 바꾸면 완료일/취소일 자동 기록 (날짜검색에 바로 반영)
  - 휴지통(선택삭제/복구/영구삭제), 페이지네이션, 엑셀 다운로드(검색 결과 그대로)
- **전자계약**
  - 계약서 보기(인쇄/PDF 저장) → 고객 서명요청 → 서명 링크 생성 (복사 / 알림톡 템플릿으로 전송)
  - 고객용 서명 페이지 `#/sign/<토큰>`: 계약 내용 확인, 동의 체크, 손서명(마우스/터치) → 서명완료
  - 서명완료 후 금액/시공내용이 바뀌면 자동으로 서명 초기화 (재서명 필요)
- **계약자관리**: 검색, 등록/수정/삭제, 연락처 중복 표시, 계약 수, 엑셀. 계약 등록 시 연락처 기준 자동 등록/연결
- **일정관리**: 계약 데이터 기반 달력, 기사별 건수, 필터, 날짜 상세, 회차별 일정/기사 변경, 기사 알림톡, 엑셀
- **진행상황**: 상태별/서명상태별 건수, 기사 미배정 건수, 7일 내 시공 예정 목록
- **통계정보**: 기간+날짜기준 선택, 월별/구분별/브랜드별/접수형태별/작성자별 건수·금액, 엑셀
- **계정관리**: (운영자) 상단 [업체/계정관리]에서 업체 등록·수정·이용기간 연장·정지, 관리자 추가/비밀번호 재설정/중지
- **설정** (관리자, 또는 `기사/팀/상품/아파트 관리` 권한을 받은 실장)
  - 사용자관리: 실장 등록, 부서(팀)/직책, 메뉴 권한 체크, 데이터 범위, 중지/재개 — 비밀번호는 암호화 저장, 화면에 노출하지 않고 재설정만 가능
  - 기사관리: 품목/연락처/아이디(추후 기사모바일 로그인용). 배정 이력이 있는 기사는 삭제 시 "미사용" 처리
  - 팀관리 / 상품관리(구분·품목·상세품목·금액·노출여부) / 아파트관리(시도·시군구·아파트명)
  - 계약 등록 화면 연동: **상품선택** 시 시공내용·금액 자동 입력, 아파트명 자동완성
  - 일정관리설정: 참고 화면 받은 뒤 구현 예정

## 5. 코드 구조

```
frontend/src
├─ api/
│  ├─ index.js       화면이 쓰는 입구: 데모 모드면 직접 실행, 서버 모드면 remote.js 로 서버 요청
│  ├─ services.js    인증/계정/기초코드/계약자 (브라우저·서버 공용)
│  ├─ runtime.js     실행 환경 연결부 (저장·세션·암호화)
│  ├─ browserAdapter.js / remote.js  데모 모드 저장소 / 서버 요청
│  ├─ core.js        세션·권한 검사 공통 (= 서버 인증 미들웨어)
│  ├─ contracts.js   계약·변경이력·전자서명·알림톡·통계
│  ├─ schedule.js    일정·기사 휴무 규칙·기사모바일·일정관리설정
│  ├─ views.js       계약 화면용 가공(금액 숨김 등)
│  └─ seed.js        샘플 데이터 + 데이터 이전(마이그레이션)
├─ auth/
│  ├─ permissions.js 역할/권한 키/위임 규칙
│  └─ AuthContext.jsx 로그인 상태, can(), 공통 에러 처리
├─ pages/            로그인, 계약관리, 계약서 작성(ContractEditor), 기사모바일(EngineerApp), 통계, 설정, 고객 서명
├─ components/       검색필터, 계약표, 계약 등록/보기 모달, 알림톡, 계약자, 일정, 진행상황
├─ utils/            날짜(YYYY-MM-DD 문자열 비교), 금액 계산, 전화번호 포맷, 엑셀
└─ constants.js      브랜드/구분/상태 코드값 (추후 설정 메뉴로 이전)
```

금액은 저장하지 않고 항상 `시공총액 - 할인 - 상품권 - 입금합계` 로 계산해 불일치가 생기지 않게 했습니다 (`utils/contract.js`).

## 6. 백엔드 선택: Supabase vs Google Cloud

**결론: 오래 쓸 서비스라도 Supabase(서울 리전)로 시작해도 됩니다. 다만 "Supabase 전용 기능에 묶이지 않게" 만드는 것이 핵심입니다.**

| | Supabase | Google Cloud (Cloud Run + Cloud SQL) |
|---|---|---|
| DB | PostgreSQL (표준) | PostgreSQL/MySQL (표준) |
| 서울 리전 | 있음 | 있음 |
| 초기 구축 속도 | 빠름 (DB·인증·파일저장·백업 기본 제공) | 느림 (네트워크·권한·배포 직접 구성) |
| 월 비용(소규모) | 실서비스는 Pro 요금제 필요 (무료는 비활성 시 일시정지, 백업 없음) | DB 인스턴스가 상시 과금이라 보통 더 비쌈 |
| 운영 부담 | 낮음 | 높음 (대신 세밀한 통제 가능) |
| 나중에 이전 | DB 가 표준 Postgres 라 `pg_dump` 로 이전 가능 | — |

"오래 쓴다"에서 실제로 중요한 것은 **나중에 옮길 수 있느냐**입니다. 그래서 이렇게 권장합니다:

1. **DB 는 Supabase 의 Postgres 를 "그냥 Postgres"로 사용** — 테이블/인덱스/마이그레이션 파일을 표준 SQL 로 관리
2. **화면에서 Supabase 를 직접 호출하지 않고, 우리 API 서버를 한 층 둠** — 지금 `src/api/index.js` 에 모아 둔 권한 검사를 그대로 서버로 옮김. (Vercel Functions 또는 Cloud Run 에서 실행)
3. 이렇게 하면 규모가 커져서 Google Cloud / AWS / 네이버클라우드로 옮길 때 **DB 덤프 + 서버 재배포**만 하면 됩니다

추가 고려사항:
- 고객 이름·전화번호·서명을 다루므로 **개인정보 보호**가 중요합니다: 국내(서울) 리전 사용, 접근기록 보관, 백업 필수.
- 공공기관/대기업 납품 계획이 있으면 국내 클라우드 인증(CSAP)이 요구될 수 있어 네이버클라우드·KT 가 유리할 수 있습니다. 일반 업체 대상이면 해당 없음.
- 알림톡(비즈고)은 백엔드가 생긴 뒤 서버에서 호출합니다 (API 키가 브라우저에 노출되면 안 되기 때문).

### 계약서 작성 화면 (참고 화면 기준, 모달 → 전체 페이지)
1. **계약정보**: 브랜드 · 고객명(검색, 등록 후 수정 불가) · 연락처①② · 계약담당(관리자는 변경 가능) · 현장(아파트 자동완성 + 동/호/타입/평) · 계약일 · 입주예정일 · 계약승인 · 기타사항

   - 시공상태(최종): 미정 / 해피콜완료 / 배정 / 시공완료(완료일) / 시공연기 / 취소(사유·취소일) → 고객 계약서 링크에 표시
3. **(추가) 시공내역·금액**: 상품선택 → 상품 라인(수량·단가) 합계로 시공총액 자동 계산, 할인/상품권, 입금 내역(계약금/잔금 · 카드/현금/계좌이체)
4. **(추가) 해피콜 메모**, **변경이력**(누가 언제 무엇을 바꿨는지 자동 기록)
5. 계약승인: 실장이 등록하면 '승인대기' → `계약 승인` 권한자가 계약서 또는 목록(선택 승인)에서 처리. 목록 계약자 옆에 (승인) 표시

### 기사 휴무 규칙
| 휴무 | 배정 가능한 일정 |
|---|---|
| 종일 | 없음 |
| 오전 | 오후 시간 또는 '오후(시간미정)' |
| 오후 | 오전 시간 또는 '오전(시간미정)' |

- 오전/오후 기준 시각은 설정 > 일정관리설정 (기본 12:00)
- 시간을 정하지 않은 일정은 어느 쪽인지 알 수 없으므로 반일 휴무 기사에게 배정 불가
- 반대로 이미 배정된 시간대에는 휴무 등록 불가 (일정을 먼저 옮기도록 안내)
- **팀배정**: 팀원(사용 중인 소속 기사) **전원이 그 시간대에 휴무일 때만** 배정 불가. 한 명이라도 일할 수 있으면 배정 가능.
  팀 일정이 있는 시간대에 마지막 남은 팀원이 휴무를 넣으려 하면 등록 불가. 팀 선택 목록에 "(2명, 휴무 1명)" / "— 전원 휴무" 표시
- 모든 검사는 서비스 계층(`api/schedule.js`)에서 수행 → 화면을 우회해도 차단
- 표시: 달력 칸 상단 파란 '휴무' 박스에 `종일`/`오전`/`오후` 칩 + 기사명, 날짜 상세에 사유, 계약서의 기사 선택 목록에 "— 오전휴무" 표시 및 선택 불가

### 기사모바일
- 설정 > 기사관리에서 아이디/비밀번호를 등록하면 같은 로그인 화면에서 기사용 화면으로 진입 (데모: `gong / gong1234`)
- 내 일정(본인 배정 + 소속 시공팀 배정), 회차별 상태 보고(시공완료/시공연기요청/시공불가 + 메모) → 계약서 '모바일웹'에 즉시 표시
- 휴무 설정: 달력에서 날짜 선택 → 오전/오후/종일 + 사유 (참고 팝업과 동일), 휴가취소

## 8. 서버 연결 구조 (4차 작업)

```
화면(frontend) ──POST /api/rpc {service, method, args}──▶ 서버(api/rpc.js → server/handler.js)
                                                            │ 같은 업무 코드(frontend/src/api/services.js) 실행
                                                            ▼
                                                   PostgreSQL (Supabase 서울)
```

- **같은 코드, 두 환경**: 업무 로직은 `runtime.js` 를 통해 저장·세션·암호화 기능을 받아 씁니다.
  데모 모드는 `browserAdapter.js`(localStorage), 서버는 `server/handler.js`(PostgreSQL)를 연결합니다.
- **요청 처리 순서**: 쿠키로 로그인 사용자 확인 → 그 업체 데이터만 읽기 → 업무 코드 실행(권한 검사) → 바뀐 행만 저장.
  오류가 나면 저장하지 않습니다(되돌림). 쓰기 요청은 DB 잠금으로 순서대로 처리해 동시 수정 충돌과 번호 중복을 막습니다.
- **보안**
  - 로그인 쿠키: 서명 + HttpOnly(화면 스크립트로 못 읽음) + SameSite + HTTPS 전용, 12시간
  - 비밀번호: scrypt + 사용자별 salt 로 암호화 저장, 응답에 절대 포함 안 함
  - 로그인 5회 실패 시 10분 잠금
  - 호출 가능한 함수 목록 외 요청 거부, 데이터 초기화 기능은 서버에서 차단
  - Supabase 표는 RLS 를 켜서 브라우저에서 직접 접근 불가 (서버만 접근)
  - 전자서명 증빙에 서명자 IP·기기 정보 기록
- **DB 자동 준비**: 서버가 처음 켜질 때 표 생성 + 최초 운영자 계정 발급 (여러 서버가 동시에 켜져도 한 번만)
- **표 구조**: 각 표는 `id / company_id / data(JSON)`. 업무 코드의 데이터 형태를 그대로 저장해 두 모드가 같은 코드를 쓰도록 했습니다.
  업체 수·계약 수가 많이 늘면(수만 건 이상) 자주 검색하는 항목을 별도 컬럼으로 분리하는 것이 다음 단계입니다.

### 서버 시험 결과 (로컬 PostgreSQL 16)
- 비로그인·권한 없는 요청 차단, 실장의 남의 계약 직접 조회 차단(404), 기사의 계약 목록 접근 차단
- 동시 계약 등록 10건 → 모두 성공, 계약번호 중복 없음
- 휴무 규칙·기사 보고·전자서명(비로그인 링크)·로그인 잠금·로그아웃이 서버에서도 동일하게 동작
- 빈 DB 에서 첫 요청 5개가 동시에 와도 표/운영자 계정이 한 번만 생성
- 새 업체 발급 → 관리자 로그인 → 기사/실장 발급 → 계약 등록 전체 흐름

## 9. 계약 번호 · 계약 상세 화면 (5차 작업)

- **번호 = 계약일 순서**: 가장 오래된 계약이 1번, 최신 계약이 전체 건수. 번호는 저장하지 않고 매번 계산하므로
  예전 날짜 계약을 나중에 등록해도 그 날짜 위치에 번호가 들어갑니다. 휴지통 계약은 번호에서 제외 (`api/numbering.js`).
- **목록**: 기본 정렬 번호순. 줄에 마우스를 올리면 강조되고 누르면 계약 상세로 이동.
- **계약 상세** (`pages/ContractDetail.jsx`) — 같은 계약자 + 같은 현장(아파트/동/호)의 시공들을 한 계약으로 묶어 표시
  - 시공관리 탭: 기본정보, 시공정보(선택한 시공), 상세시공(+시공등록, 알림톡 기사배정/계약완료 × 브랜드, 수정/삭제),
    시공별 계약금액(매출취소·실계약·입금·환불·남은금액), 입금(+입금등록, 수정/삭제), 진행상황(기사 보고)
  - 계약정보 탭: 기본정보 + 묶음 전체 변경이력 / 계약자 탭: 계약자 정보 + 다른 현장 계약 / 상담내역 탭: 상담 기록
- **금액 계산**: 남은금액 = (실계약금 − 매출취소) − (입금 − 환불). 취소된 시공은 매출취소로 처리.
- **입금 항목**: 입금자명, 승인번호, 카드사/은행, 카드번호(**끝 4자리만 저장**), 영수증 구분, 비고
- **추가 항목**: 기사전달사항(기사모바일에 표시), 세금계산서·현금영수증 발행 상태
